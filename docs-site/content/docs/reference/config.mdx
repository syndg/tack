## Config Model

Tack merges config in this order:

1. built-in defaults
2. user config at `~/.config/tack/config.yaml`
3. project config at `<repo>/.tack/config.yaml`

`tack daemon` reads the user layer. Project-scoped commands read the merged result.

## Complete Example

```yaml
daemon:
  listen: "0.0.0.0:9800"          # default machine-wide listen address
  external_url: ""                # required for remote callback flows
  data_dir: "~/.config/tack/data" # default runtime state directory
  base_branch: "main"

sandbox:
  provider: "daytona"             # default is daytona; switch to local for faster dev loops
  worktree_dir: ""
  default_resources:
    cpu: 2
    memory: 2048
    disk: 10
  auto_stop_interval: 30
  auto_delete_interval: 1440
  daytona:
    api_url: ""
    snapshot: ""

project_setup:
  commands:
    - "bun install"
  verify:
    - "bun --version"

agents:
  runtime: "claude-code"
  max_concurrent: 8
  max_depth: 2
  stagger_delay_ms: 500
  idle_timeout_minutes: 15
  pi:
    provider: "anthropic"
    model: ""
    thinking_level: "medium"
    extension_path: ""
  timeouts:
    default:
      max_duration_minutes: 30
      idle_minutes: 10
    planner:
      max_duration_minutes: 20
    builder:
      max_duration_minutes: 45
    reviewer:
      max_duration_minutes: 15

runtime_auth:
  mode: tack
  runtime: pi
  provider: openai-codex
  method: oauth
  credential_ref: openai-codex

models:
  default: gpt-5.4
  agent: gpt-5.4
  planner: gpt-5.4
  small_tasks: gpt-5.4-mini
  deterministic: gpt-5.4-mini

planning:
  default_mode: collaborative
  model: ""

watchdog:
  check_interval_seconds: 30
  nudge_after_minutes: 10
  escalate_after_nudges: 3

tools:
  max_per_agent: 20
  always_include: []
  always_exclude: []

git:
  author_name: Tack
  author_email: tack@local

quality_gates:
  - "bun test"
  - "bunx tsc --noEmit"
  - "bun run lint"
```

## Key Fields

### `daemon`

- `listen` - HTTP bind address for the daemon
- `external_url` - public callback URL for remote sandboxes
- `data_dir` - machine-wide runtime state, including activity logs
- `base_branch` - base branch used for worktrees and merge

### `sandbox`

- `provider` - `local` or `daytona`
- `worktree_dir` - override local worktree root
- `default_resources` - integer CPU, memory, and disk values
- `auto_stop_interval` - idle shutdown for Daytona sandboxes
- `auto_delete_interval` - Daytona cleanup window
- `daytona.snapshot` - snapshot ID to reuse for remote startup speed

`sandbox.post_create` still exists as a deprecated compatibility input, but new configs should use `project_setup.commands`.

Practical guidance:

- use `local` for the fastest inner-loop development and test runs
- use `daytona` for remote or production-style isolation

### `project_setup`

- `commands` - setup commands to run after sandbox creation
- `verify` - lightweight checks for the setup stage

### `agents`

- `runtime` - currently `pi` or `claude-code`
- `max_concurrent` - max worker sessions at once
- `max_depth` - nested depth limit for agent spawning
- `stagger_delay_ms` - delay between spawns
- `idle_timeout_minutes` - coarse watchdog timeout
- `timeouts.*` - per-role max duration and idle limits

### `runtime_auth`

Controls how the selected runtime authenticates to the chosen provider.

- `mode` - `native` or `tack`
- `runtime` - runtime name
- `provider` - provider used by that runtime
- `method` - `api_key` or `oauth`
- `credential_ref` - provider key in the credentials store

### `models`

Model selection is now split by purpose:

- `default`
- `agent`
- `planner`
- `small_tasks`
- `deterministic`

### `planning`

- `default_mode` - planning mode, currently `collaborative` by default
- `model` - legacy/shared planning model override

### `watchdog`

- `check_interval_seconds`
- `nudge_after_minutes`
- `escalate_after_nudges`

### `tools`

- `max_per_agent`
- `always_include`
- `always_exclude`

### `git`

- `author_name`
- `author_email`

## Credentials

Stored in `~/.config/tack/credentials.yaml`:

```yaml
providers:
  openai-codex:
    type: oauth
    access_token: "..."
    refresh_token: "..."
    expires_at: 0

git:
  type: pat
  host: github.com
  token: GITHUB_TOKEN

sandbox:
  daytona:
    type: api_key
    api_key: DAYTONA_API_KEY
```

Credential values can be:

- literal secrets
- environment variable names like `GITHUB_TOKEN`
- shell lookups like `!op read op://...`

## Environment Variables

There are no hardcoded environment variable field names in the config schema itself. Instead, credentials file values can point at environment variables by name.

Common examples:

- `OPENAI_API_KEY`
- `ANTHROPIC_API_KEY`
- `GITHUB_TOKEN`
- `DAYTONA_API_KEY`
