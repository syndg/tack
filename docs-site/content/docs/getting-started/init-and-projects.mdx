## The Current Model

Tack runs as a **machine-wide daemon** with **project-scoped execution**.

- User-level defaults live in `~/.config/tack/`
- Repo-local config lives in `<repo>/.tack/`
- Each registered repo gets a stable `.tack/project-id`
- CLI commands resolve the current project from your working directory

## Recommended Bootstrap Path

Run `tack init` inside your repository:

```bash
cd your-project
tack init
```

### What `tack init` Does

The init command is an interactive wizard that sets up everything Tack needs for your project:

1. **Creates `.tack/config.yaml`** — project-specific configuration
2. **Agent runtime selection** — asks which runtime to use (Pi or Claude Code)
3. **LLM provider selection** — asks which provider (Anthropic, OpenAI, etc.) and validates the choice against your selected runtime
4. **Authentication setup** — asks for API keys or initiates OAuth flows, stores them in `~/.config/tack/credentials.yaml`
5. **Sandbox provider selection** — local (git worktrees) or Daytona (remote VMs)
6. **Model selection** — default model, planner model, agent model, small tasks model
7. **Writes `.tack/project-id`** — a stable UUID that the daemon uses to identify this project
8. **Updates `.gitignore`** — appends local runtime artifacts (`.tack/project-id`, `.tack/*.db`) while keeping config, blueprints, and rules committable
9. **Registers with the daemon** — if the daemon is reachable, registers the project immediately

Every choice the wizard makes is validated. If you pick an incompatible combination (e.g., native auth with Daytona sandboxes), the wizard will tell you before proceeding.

## Start the Daemon

`tack daemon` reads the user config layer, not a per-project config file:

```bash
tack daemon
```

The daemon starts in the foreground. Open a new terminal for CLI commands.

## Project Commands

You can manage registrations explicitly:

```bash
tack project add .                    # Register the current repo
tack project list                     # List all registered projects
tack project inspect                  # Show current project details
tack project relink <id> <new-path>   # Move an existing registration
tack project remove <id>              # Unregister a project
```

Most project-scoped commands resolve the current repo automatically from your working directory. If you need to target another repo:

```bash
tack plan "description" --project <project-id>
tack plan "description" --project /path/to/other/repo
```

## Multiple Projects

The daemon supports multiple registered projects. Each project has its own:

- Config (`.tack/config.yaml`)
- Blueprints (`.tack/blueprints/`)
- Rules (`.tack/rules/`)
- Database (`.tack/tack.db`)
- Activity logs

When you run a CLI command, Tack resolves the project from your current working directory. This means you can have two repos registered and use Tack in both without switching contexts.

## Auth Commands

You can also manage credentials directly (outside of `tack init`):

```bash
tack auth add anthropic       # Add Anthropic API key
tack auth add openai-codex    # Add OpenAI Codex OAuth
tack auth add git             # Add GitHub PAT for PR creation
tack auth add daytona         # Add Daytona API key
tack auth list                # Show all configured providers
tack auth test anthropic      # Validate a credential works
```

See the [Credentials & Auth guide](/docs/guides/credentials) for full details on credential formats, multi-provider setup, and security.
