## Prerequisites

Before installing Tack, make sure you have:

| Requirement | Minimum Version | Why |
|-------------|----------------|-----|
| **Go** | 1.22+ | Tack uses Go 1.22+ standard library features |
| **Git** | 2.5+ | Worktree support, branch management |
| **LLM API key** | — | At least one provider key (Anthropic, OpenAI, etc.) |

Optional:

| Requirement | Why |
|-------------|-----|
| **Node.js / npm** | Required if using the Pi runtime (Tack installs Pi via npm in sandboxes) |
| **Daytona account** | Required only for remote sandboxes |
| **GitHub PAT** | Required for automatic PR creation |

## Install from Source

```bash
git clone https://github.com/syndg/tack.git
cd tack
go build -o tack ./cmd/tack/
```

Move the binary to your `$PATH`:

```bash
mv tack /usr/local/bin/
```

## Verify

```bash
tack version
```

## What Gets Installed

Tack is a single binary. It does not install system services, background agents, or daemons automatically. You start the daemon explicitly when you want to use it:

```bash
tack daemon
```

Runtime state lives in two places:

| Location | Contents |
|----------|----------|
| `~/.config/tack/` | User-level config, credentials, activity logs, data directory |
| `<repo>/.tack/` | Per-project config, blueprints, rules, SQLite database |

The `.tack/` directory is created by `tack init`. Sensitive files like `tack.db` and `project-id` are gitignored. Config, blueprints, and rules are intentionally committable so your team shares them.
