Recommended path: run `tack init` and let Tack generate `.tack/config.yaml` for the current repo.

If you want to author the file directly, start with something like this:

```yaml
sandbox:
  provider: local

project_setup:
  commands:
    - "bun install"

agents:
  runtime: pi
  max_concurrent: 4
  stagger_delay_ms: 1000
  pi:
    provider: openai-codex
  timeouts:
    default:
      max_duration_minutes: 30
      idle_minutes: 10
    builder:
      max_duration_minutes: 45
    reviewer:
      max_duration_minutes: 15

runtime_auth:
  mode: tack
  runtime: pi
  provider: openai-codex
  method: oauth
  credential_ref: openai-codex

models:
  default: gpt-5.4
  agent: gpt-5.4
  planner: gpt-5.4
  small_tasks: gpt-5.4-mini

watchdog:
  check_interval_seconds: 30
  nudge_after_minutes: 10
  escalate_after_nudges: 3

tools:
  max_per_agent: 20

git:
  author_name: Tack
  author_email: tack@local

planning:
  default_mode: collaborative

quality_gates:
  - "bun test"
  - "bunx tsc --noEmit"
  - "bun run lint"
```

## Credentials

Credentials live in `~/.config/tack/credentials.yaml` and are usually managed through `tack init` or `tack auth`.

Current file shape:

```yaml
providers:
  openai-codex:
    type: oauth
    access_token: "..."
    refresh_token: "..."

git:
  type: pat
  host: github.com
  token: GITHUB_TOKEN

sandbox:
  daytona:
    type: api_key
    api_key: DAYTONA_API_KEY
```

Provider and sandbox secrets can be stored as literal values, environment variable names, or `!command` lookups.

## Project Layout

```
.tack/
  config.yaml          # Project-layer config
  project-id           # Stable project identity used by the daemon
  blueprints/          # Optional project overrides or custom workflows
    standard.yaml
    build-review.yaml
  rules/               # Project-specific prompt/rule files
    payments.md
```

Defaults also exist at the user layer under `~/.config/tack/`. Tack merges config as:

1. built-in defaults
2. user config
3. project config
